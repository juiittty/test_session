# explain-code: 한국어 설명 주석 달기

사용자는 코딩 초보자다. 사용자가 준 파일을 읽고, 이해하기 쉬운 한국어 설명 주석을 **원본 파일에 직접** 단다.
목표는 사용자가 나중에 파일을 열었을 때 주석만 읽고도 "이 파일이 무엇을 하고, 각 부분이 왜 있는지" 알 수 있게 하는 것이다.

대상 파일: $ARGUMENTS

## 1. 시작 전 확인

- 경로가 비어 있으면 어떤 파일에 주석을 달지 물어본다.
- 다음 경우에는 주석을 달지 말고 이유를 설명한 뒤 어떻게 할지 물어본다.
  - 프로젝트 폴더 밖의 파일이거나 `node_modules/`, `.next/`, `package-lock.json`처럼 자동으로 만들어지는 파일인 경우. 이런 파일은 고쳐도 다시 덮어써지거나 프로그램이 망가질 수 있다.
  - 주석을 쓸 수 없는 형식인 경우(`.json` 등). 이때는 파일 대신 채팅으로 설명해도 되는지 물어본다.
- 파일에 이미 `[설명]` 주석이 있으면 다시 달지(기존 `[설명]` 주석은 지우고 새로 작성), 그대로 둘지 물어본다.

## 2. 코드 이해하기

- 파일 전체를 읽는다. import한 프로젝트 내부 파일도 필요한 만큼 읽어서 흐름을 파악한다.
- Next.js 관련 코드는 `node_modules/next/dist/docs/`에서 확인한다. 이 프로젝트의 Next.js 16은 예전 버전과 다른 점이 많아서 기억에 의존하면 틀린 설명을 쓰기 쉽다.
- 확인해도 무엇을 하는지 확실하지 않은 부분은 **추측해서 주석으로 쓰지 않는다.** 틀린 설명은 초보자에게 설명이 없는 것보다 더 해롭다. 그런 부분은 마지막 채팅 요약에서 "확인하지 못한 부분"으로 알려준다.

## 3. 주석 달기 전에 원본 저장

주석을 달기 전에, 나중에 코드가 바뀌지 않았는지 비교할 수 있게 원본을 저장한다.

```bash
node .claude/skills/explain-code/scripts/check-only-comments.mjs snapshot <파일>
```

## 4. 주석 다는 규칙

### 무엇을 쓸까
- **파일 맨 위 요약**: 이 파일이 무엇을 하는 파일인지, 어떤 화면이나 기능과 연결되는지 2~4줄로 쓴다.
- **덩어리 설명**: import 묶음, 함수, 컴포넌트, 조건문, JSX 구역처럼 의미 있는 덩어리 바로 위에 1~3줄로 "무엇을 하는지, 왜 필요한지"를 쓴다. 모든 줄에 달지 않는다.
- 전문 용어는 처음 나올 때 괄호로 짧게 풀어준다. 예: `컴포넌트(화면의 한 조각을 만드는 함수)`
- 코드를 그대로 읽어주는 주석(`// x에 1을 더한다`)은 쓰지 않는다. 그 코드가 **왜** 있는지, **결과로** 무엇이 일어나는지를 쓴다.
- 존댓말("~해요")로 쓴다.

### 어떻게 쓸까
- 모든 설명 주석에 `[설명]` 표시를 붙인다. 나중에 사용자가 검색하거나 한꺼번에 지울 수 있게 하기 위해서다.
- **주석은 한 줄에 하나씩, 코드와 다른 줄에** 쓴다. 코드 줄 끝에 붙이거나 여러 줄짜리 `/* */`를 쓰면 검사 스크립트가 주석과 코드를 구분하지 못한다.
- 파일 종류별 주석 모양:
  - `.ts` `.tsx` `.js` `.mjs`: `// [설명] ...`
  - JSX 안쪽(태그 사이): `{/* [설명] ... */}`
  - `.css`: `/* [설명] ... */`
- 주석 줄은 들여쓰기를 바로 아래 코드에 맞춘다.
- 빈 줄은 새로 넣거나 지우지 않는다. 맨 위 요약 주석 아래에도 빈 줄을 더하지 않는다. 검사 스크립트는 빈 줄도 코드의 일부로 비교한다.
- 기존 주석은 그대로 둔다. 영어 주석이 있으면 지우거나 고치지 말고, 필요하면 그 아래에 한국어 `[설명]` 주석을 더한다.
- **코드는 한 글자도 바꾸지 않는다.** 오타나 버그가 보여도 고치지 말고 채팅 요약에서 알려준다. 이 스킬은 설명용이고, 코드 변경은 사용자가 따로 요청해야 한다.

### 예시

```tsx
// [설명] 이 파일은 모든 페이지를 감싸는 공통 틀(레이아웃)이에요.
// [설명] 글꼴과 전체 배경처럼 모든 화면에 똑같이 들어가는 부분을 여기서 정해요.
import type { Metadata } from "next";

// [설명] 브라우저 탭에 보이는 제목과, 검색엔진에 보여줄 설명을 정해요.
export const metadata: Metadata = {
  title: "Create Next App",
};

export default function RootLayout({ children }: LayoutProps<"/">) {
  return (
    <html lang="en">
      {/* [설명] children은 지금 열려 있는 페이지의 내용이에요. 이 틀 안에 끼워져서 보여요. */}
      <body>{children}</body>
    </html>
  );
}
```

## 5. 코드가 바뀌지 않았는지 확인

```bash
node .claude/skills/explain-code/scripts/check-only-comments.mjs check <파일>
```

- `OK`가 나오면 다음 단계로 넘어간다.
- 실패하면 바뀐 줄을 원래대로 되돌리고 다시 확인한다. 주석을 코드 줄 끝에 붙였거나 여러 줄 주석을 썼을 때도 실패하니 그 부분도 확인한다.
- `.ts` `.tsx` 파일이면 `npm run lint`도 실행해서 주석 때문에 생긴 문제가 없는지 본다. 원래부터 있던 경고는 따로 알려주기만 한다.

## 6. 채팅으로 짧게 요약

파일마다 아래 형식으로 짧게 알려준다.

```
### <파일 경로>
이 파일이 하는 일: (3~5줄 요약)

새로 나온 용어
- 용어: 한 줄 설명

(있을 때만) 확인하지 못한 부분 / 눈에 띈 문제
- ...
```

마지막 줄에 "설명 주석은 `[설명]`으로 검색하면 모두 찾을 수 있어요."라고 덧붙인다.
